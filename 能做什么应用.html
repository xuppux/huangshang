小智 AI 能不能装进来

能，但「放进去」有三种完全不同的意思，难度差了 100 倍。下面把三条路都摊开。

先给结论：小智在黄山派上是官方支持的现成固件（虾哥的 78/xiaozhi-sf32 支持硬件列表里就有立创黄山派）。 但它是一套整机固件，不是一个能被蜂窝列表加载的 app。 所以「当一格图标点进去」这件事，需要你把它的能力移植进手表工程，而不是「安装」。
怎么联网蓝牙 PAN —— 手机开「蓝牙网络共享」当网关。不需要 WiFi 模块，这块板子也没有 WiFi。
手机要求需要安卓手机。iPhone 不给第三方设备共享蓝牙网络，这条路 iOS 走不通。
要装什么一个小喇叭接到板上的 Speaker 座（板载 3W 功放），麦克风板子自带了。
服务器连 xiaozhi.me，手机号登录后在控制台绑设备码。

三条路对比

做法最后是什么样工作量风险
A · 整体换掉 烧官方小智固件，板子变成一个小智音箱（带屏）。手表功能全部没有了 一个下午 低，烧回来就行
B · 移植成一个 app ← 真·「放进蜂窝」 蜂窝里多一格「AI 对话」，点开说话，退出回表盘。手表功能都还在 ★★★★ 大工程 中：音频、内存、蓝牙要和现有功能抢资源
C · 手机当网关 手表只负责录音+放音，识别和大模型跑在手机 App 里 ★★★ 中：要自己写手机端
D · 装两份固件来回切 开机时选「手表」还是「小智」 ★★★★ 高：要改分区表和引导程序，不建议新手碰

路径 A · 只想先看看小智长什么样（推荐先做这个）

  1. 把小喇叭接到板上的 Speaker 座。
  2. 先备份现在的固件（这步别省）：把 build_sf32lb52-lchspi-ulp_hcpu\main.bin 复制成 main.backup.bin 存到别处。
  3. 从 github.com/78/xiaozhi-sf32/releases 下最新固件压缩包，里面有 5 个 bin。
  4. 用 sftool 按官方给的地址烧进去（bootloader / ftab / ER_IROM1~3）。
  5. 手机开「蓝牙网络共享」→ 蓝牙里连上 sifli-pan → 按对话键 → 手机浏览器打开 xiaozhi.me 绑设备。
  6. 想回到手表：直接跑 watch\flash.ps1 把备份的 main.bin 烧回来。
备份为什么重要 小智固件自带自己的分区表（ftab），烧进去会覆盖现在的。所以除了 main.bin，稳妥起见也把当前的 ftab 读出来存一份 （sftool read_flash 0x12000000 0x8000 ftab.backup.bin，具体参数以 sftool --help 为准）。 这样万一恢复时起不来，两样都能按原样烧回去。

路径 B · 想真的做成蜂窝里的一格

好消息是：小智要用的每一块料，SDK 里都已经有了，不用你自己啃协议栈。

小智需要的能力SDK 里现成的东西
通过蓝牙上网middleware/bluetooth/porting/rtt/bt_pan/ —— 已经做成一张 lwip 网卡，连上就能拿到 IP
TCP/IP 协议栈rtos/rtthread/components/net/lwip
语音编解码 Opusexternal/opus-1.4/ —— 完整源码，而且 middleware/acpu_ctrl/ 里已经按小智的参数（16kbps、20ms 帧、语音模式）配好了
录音 + 播放middleware/audio/audio_manager，示例在 example/multimedia/audio/record
回声消除（不然喇叭的声音会被自己听进去）external/WebRTC_audio_processing

要补的开关（都在 proj.conf）：

# 蓝牙上网 CONFIG_CFG_PAN=y CONFIG_BT_FINSH_PAN=y # 音频链路 CONFIG_AUDIO_USING_MANAGER=y # 网络（lwip + DHCP 客户端） CONFIG_RT_USING_LWIP=y

真正的四个坑，提前知道能省几周：

  1. WebSocket 得自己写。SDK 只有 HTTP 客户端（external/webclient），没有 WebSocket。要么自己实现握手+分帧（大约几百行），要么改成 MQTT/UDP 那套协议。
  2. 蓝牙要共存。现在的校时用的是 BLE，小智用的是经典蓝牙 PAN。芯片支持双模同时跑，但连接管理要重新理一遍，否则两个功能会互相踢。
  3. 内存要重算。音频缓冲 + 网络缓冲都吃内存。Flash 够用（现在 2.5MB，main 分区有 8MB），但 PSRAM/SRAM 得实际算一遍。
  4. 手机必须是安卓，而且用户得知道去开「蓝牙网络共享」——这个入口藏得比较深，最好在手表屏幕上给出提示。
我的建议 先用路径 A 花一个下午把官方小智烧进去玩一玩，亲身体会一下「延迟、音质、联网稳定性」到底什么样。 玩过之后再决定要不要走 B —— 因为 B 是个大工程，而 A 的成本几乎为零，先花小钱判断值不值得。 另外路线 B 有个更划算的中间态：先把「录音 10 秒 + 回放」接通（SDK 有现成例子）， 这一步做完，你就有了语音功能的地基，界面反而最好补。

如果不知道从哪下手，先做这三个

这三个的共同点：板上硬件全都在、SDK 里全都有现成代码、做完了立刻能看见效果，而且彼此不打架。

1
状态栏显示电池电量

现在屏幕右上角是空的，连电池图标都没有 —— 这是拿电池供电的表最该有、却最缺的一块。

ADC 的 CH7 已经内部接到了电池正极（不用外接分压电阻），先加 CONFIG_BSP_USING_ADC1=y，照 adc 例程读 bat1 就行。
2
抬腕亮屏

把手抬起来看时间，屏幕自动亮 —— 这是「手表感」最强的一个功能，比任何新界面都值。

加速度计（LSM6DS3TR-C）走 I2C3（PA39/PA40），打开 CONFIG_BSP_USING_I2C3=y 后照 RT-Device/sensor 例程读角度，再调现成的 app_watch_set_brightness()。
3
计步器

今天走了多少步。做出来直接就是蜂窝里的一格。

比想象的简单：LSM6DSL 驱动自带计步算法，设备名 step_lsm，读一次就是步数，算法完全不用自己写。
依据：rtconfig.h（当前固件实际开关）+ board.conf（板级器件）+ 立创官方规格 + SDK 源码树实际文件。 整理于 2026-09-21，对应固件 main.bin 2,514,740 字节那一版；2026-09-23 更新到 2,568,732 字节那一版。
已经做掉的：计算器（删掉卡片左上角返回键、算式行加宽 254 → 334）、 手电筒（进 app 默认常亮，轻触循环 关 → 常亮 → 5Hz 频闪，屏幕全白 + 背光 100%， 1s 定时器顶住自动息屏）、 2048（四方向共用一段合并逻辑、一步撤销、防息屏、11 条串口自检命令； 浏览器可玩版在 watch/ui-preview/game2048.html； 09-23 连做两轮真机返工：① 去掉底部「第 N 步」那行、修掉分数面板里汉字标题压数字 （根因是 label 占的高度是行高不是字号：16px 的 label 实际 25px 高）； ② 按反馈删掉左上角「2048」标题、两个分数/最佳面板整体顶部居中， 并把棋盘位置改成由信息条算出来（BOARD_Y = TOP_Y + PANEL_H + BAND_GAP）， 面板底和棋盘顶之间留出 6px 的缝 —— 之前是 0px，两个同色方块贴在一起 看着就像压在棋盘上）。 蜂窝里实际显示 6 格（串口敲 calc_menu 可复核：calculator / clock / game2048 / hello_world / rotation3d / torch），离 16×16 的上限还早得很 —— 所以「加不下」从来不是理由。
