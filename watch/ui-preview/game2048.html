字号是跟着数字长度变的

格子只有 71px 宽，131072 这种 6 位数按 36px 会画出格子。所以 font_for() 按数量级降字号： <100→36 / <1000→28 / <10000→24 / <100000→20 / 其余→16。 右下角那个「摆残局」按钮会往盘上塞 65536，就是专门验这一条的。

另一件容易返工的事：棋盘不能压这两条边 已经在编译期卡死

这块屏的 layer_top 上有两条系统手势条：顶部 34px 是上划， 右边缘 x≥374 那 16px 是左滑返回。 如果棋盘最右边压到 374，玩家想把最右列往右划，系统会当成「退出 app」—— 现象是「某一列死活划不动」，而代码怎么看都对。

所以这三个数写成编译期断言，不靠记性： 

#if (BOARD_X + BOARD_W) >= RIGHT_BAR_X   /* 357 >= 374 */
#error "board overlaps the right-edge swipe-back bar (x >= 374)"
#endif
#if (BOARD_Y + BOARD_W) > BOT_Y          /* 413 > 416 */
#error "board overlaps the bottom button bar"
#endif
#if (BOARD_X < 20)
#error "board overlaps the left-edge gesture bar (x < 20)"
#endif

同一招也用在「顶部信息条」上。这块真机上出过两次事：先是 汉字标题和分数叠在一起（根子是 label 的高度是行高不是字号， 16px 的 label 实际占 25px），后来是分数框底部压在棋盘上 —— 那其实不是"真叠了"，是余量正好 0px，两个 #BBADA0 的方块贴在一起，边线糊成一条，看起来就是压上去了。

所以棋盘的位置现在改成"算"出来的，不再手填： BOARD_Y = TOP_Y + PANEL_H + BAND_GAP。 想把面板往上挪就只改 TOP_Y，棋盘自己跟着走 —— 间距由构造保证，"又贴到一起"不可能再发生。

合并算法：这里错一次，整局就都不对了 下面是对错并排

2048 的规则只有一条容易写错的：同一次滑动里，每块最多参与一次合并。 所以 2 2 4 往左划应该是 4 4，不是 8。 这条在屏幕上看不出区别（都是「数字变大了」），但在一次滑动里就会把分数算错、把局面带偏。

输入（一条线，往左） 正确结果 错① 下标不动 错② i += 2 说明

「错①」和「错②」不是两种笔误 —— 是两个方向的错：一个走得太少（原地打转）， 一个走得太快（跳过一对）。两种在屏幕上都只表现为"数字变大了"。

错在哪

错① 合并后下标不动。 合并会当场把 out[i] 变成两倍，并把后面几格往前挪 —— 于是 out[i] 的新值又和刚挪过来的那个数相等，下标还停在原地，就再合一次。 2 2 4 0 → 合出 4、第 1 格又是个 4 → 下标没走 → 再合 → 8。
错② 合并后 i += 2（就在这份固件里犯过）。 这个反而更隐蔽：它是看着最"保险"的写法 —— "合并过的块不能再合，那我跳过两格不就行了？" 但上面已经把后面几格往前挪了一格，下一个该比较的对子从 (i, i+1) 变成了 (i+1, i+2)。+2 正好把它跳过去， 于是 4 4 2 2 算成 8 2 2（对的是 8 4）、 4 4 4 4 算成 8 4 4（对的是 8 8）。

这个 bug 是被下面那张自检表抓出来的 —— 我第一版固件里写的就是 i += 2， 已经编好烧进表里了，是这张页面的自检让它现的原形。修正版：合并后只走一格， 靠"挪位"而不是"跳下标"来保证不重复合并。

固件里现在的写法（main.c 的 line_step()）：

/* ② 相邻相同就合并 */
i = 0;
while (i < N - 1)
{
    if (out[i] && out[i] == out[i + 1])
    {
        out[i] *= 2;
        *gained += out[i];
        for (j = i + 1; j < N - 1; j++)     /* 后面的往前挪一格 */
        {
            out[j] = out[j + 1];
        }
        out[N - 1] = 0;
    }
    i += 1;              /* ⚠ 就一格。走两格会跳过挪过来的那一对 */
}
怎么保证不再犯：别靠读代码。把 [4,4,2,2]、 [4,4,4,4]、[2,2,2,2] 这三条写进自检 —— 错①会在第一条上露馅，错②会在第一、三条上露馅。 只用 2 2 4 0 一条是测不出错②的。

四个方向共用同一段合并逻辑

上 / 右 / 下 / 左 不是写四遍。做法是：按方向把每一行（或每一列）抽成一条"从后往前"的线， 交给同一个 line_step()，再按同样的顺序写回去。四份重复代码迟早会有一份改漏。

装机之后怎么自己验 串口命令（不用猜，一条条打）

2048 在串口留了一整套命令。最要紧的是 g2048_spawn 0 —— 关掉自动生成新块之后， 棋盘就完全可控了，可以摆一个确定的残局，再验证合并到底是 4 4 还是 8。

命令干什么
g2048_info只读打印：棋盘 4 行、分数、最佳、best、moves、max、状态位（over/won/mask/snap/spawn）、防息屏定时器指针、触摸计数，以及顶部两个面板的真实几何 + 有没有重叠（panel[score] … gap=N OK / score-panel overlap check: PASS）
g2048_ui直接切到这个 app（等于点蜂窝里的图标）
g2048_new开新局
g2048_clear清空棋盘（配合 spawn 0 用）
g2048_set <r> <c> <v>往 (r,c) 摆一个值，例如 g2048_set 0 0 2
g2048_move <u|r|d|l>走一步。⚠ 会走 GUI 线程（lv_async_call），不是直接改内存
g2048_spawn <0|1>开关「自动生成新块」。验算法时必须先 0
g2048_seed <n>固定随机种子（新块位置可复现）
g2048_undo撤销一步
g2048_auto <n>自动走 n 步（压力测试，看会不会崩）
g2048_log <0|1>打开触摸日志：press x=… y=… / release dx=… dy=… dt=…ms / swipe -> 左

验证「2 2 4 不能变成 8」的完整流程

g2048_ui                 # 进 app
g2048_spawn 0            # ⚠ 关掉自动生成，不然后面摆的局会被新块污染
g2048_clear
g2048_set 1 0 2          # 第 2 行: 2 2 4 0
g2048_set 1 1 2
g2048_set 1 2 4
g2048_info               # 确认摆对了
g2048_move l             # 往左划
g2048_info               # 期望第 2 行变成  4 4 0 0 ，分数 +8
                         # 如果打出来是 8 0 0 0，就是 i += 2 写成了 i += 1
为什么必须先 spawn 0：开着自动生成的话，move 之后会随机冒出一个 2 或 4， 打出来的棋盘既有你的结果又有新块，没法一眼判对错，很容易得出「算法好像是对的」这种假结论。
触摸日志怎么用：如果出现「划了没反应」，先 g2048_log 1。 · 只有 press 没有 release → 抬起事件被别的东西吃了； · 有 release 但 dx/dy 都很小 → 手指没划够 26px（门槛在这）； · 有 release 也有位移但没有 swipe → 时长超过 1000ms，被判成「慢拖」。

这一版踩过的坑 留给下次加 app 用

坑为什么会踩 / 怎么避开
图标传 NULL，蜂窝里没这一格 代码全对、编译也过，只是主菜单不显示。BUILTIN_APP_EXPORT(名字, 图标, app id, 入口) 第二参必须给 LV_EXT_IMG_GET(img_xxx)。
图标 PNG 放哪、要不要改构建脚本 src/resource/images/common/ezip/ 下丢一张 PNG 就行，构建脚本会 Glob 出来编成同名符号。不用改任何 SConscript。
i18n 少一行 → 编译报「has no member」 LV_EXT_STR_ID(game2048) 会去查 lang_translation_t，而这个结构体是构建时从 strings/*.json 生成的。两个 json 都要加键。
防息屏定时器不删 → 别的 app 也息不了屏 2048 是「盯着想」的游戏，必须自己挂 1s 定时器 lv_disp_trig_activity()；但 on_pause / on_stop 里一定要 lv_timer_del，否则它在后台继续把系统钉醒。
子对象吃掉滑动 棋盘、16 个格子、label 全部 lv_obj_clear_flag(..., LV_OBJ_FLAG_CLICKABLE)，只让 root 可点。命中层越薄越不容易出怪事。
退出再进来棋盘空了 on_start 里判断 tile_count()：非空就重画，不重开。棋盘数值刻意不在 on_stop 里清。
