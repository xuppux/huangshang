上一版为什么会把蜂窝卡死 根因不是"写得不够好"，是这条路本身有语义冲突

上一版用手指驱动框架的手动转场接口：gui_app_manual_animation_start() → 一路 update(process) → 松手 stop(process)。 问题出在松手那一步：这个接口对「取消」和「完成」的处理方式不一样。

根因「没划够 → 弹回」在框架眼里是「这次转场作废」，而作废的收尾会回滚页面状态

SDK 用动画的结束值来判断这次转场是"完成"还是"取消"：结束值是 0 就是取消。 而手势的"弹回"恰好就是"回到 0"。取消之后的收尾回调不会切页，而是把页面状态倒回去。

// middleware/app_fwk/app_trans_anim_port.c:56 —— 结束值决定语义 if (0 == a->end_value) res = TRANS_RES_ABORTED; // 取消，留在出发页 else res = TRANS_RES_FINISHED; // 真的切页 // middleware/app_fwk/app_schedule.c:1336 —— 取消之后要"倒回去" if (TRANS_RES_ABORTED == res) { page_set_target_state(trans_anim_pg_exit, page_st_resumed); // 出发页：恢复 page_set_target_state(trans_anim_pg_enter, page_st_paused); // 目标页：暂停 app_resume(&trans_anim_pg_exit->parent->node); // 恢复出发 app }

到这里都还是对的 —— 如果那次返回还没执行的话。但上一版为了让"返回主菜单"这条路也能有跟手动画， 我改了 SDK 的一行，让返回消息在 handler 里就先把 app 退掉（app_goback()）， 然后才去搭动画。于是顺序变成了：

1. 手指划过阈值 → 消息进来 → 先真的返回了（蜂窝 RESUMED） ← 已经发生了 2. 框架搭起转场，等手指继续驱动 3. 手指划得不够 → 松手 → 结束值 = 0 → ABORTED 4. 收尾回调按"作废"处理：暂停蜂窝、恢复计算器 ← 和第 1 步冲突

结果就是状态错位：蜂窝的画面还在屏幕上，但框架认为它是 paused。 画面是 LVGL 画的，照样在刷新；可 app 层的事件分发已经停了 —— 点哪个图标都没反应。 这就是你看到的那个现象，也是我上一轮改 SDK 引进来的。

这一版的处理：完全不用手动跟手那条路。 手势只判断"要不要返回"，返回动作交给 gui_app_goback() 走框架原生的 free-run 转场 —— 那条路的结束值是固定的，没有"作废回滚"这个分支。 同时把我上一轮改的 SDK 那一行还原了（git status 已干净）。

顺带上一版还会在滑动开始时去改「当前页」的转场配置，而且不还原

为了让跟手动画用水平平移，上一版调了 gui_app_set_enter_trans_anim() / gui_app_set_exit_trans_anim() / gui_app_set_trans_anim_prio()。这三个接口写的是当前页的配置 —— 在蜂窝上滑一次，就会把蜂窝自己的转场配置改掉，且不会自动恢复，影响之后所有转场。

这一版一个字都不碰这类接口。动画只用"配置里本来就有"的那套（见下一节）。

这次改了什么 四件事，每件都有依据

改 1手势改成触发式：不再跟手，页面全程不动

手指在右边缘划的过程中，页面一个像素都不动，动的只有右边缘那条指示条。 松手时判定（划够 130px，或者快甩 60px 以上），判定通过就触发一次完整的返回动画。

好处：不再往框架的转场状态机里灌中间态 —— 上一版所有的坑都出在这里。 另外动画是"整整一段"播完，而不是像跟手那样被手指的采样节奏一段段拽着走，观感反而更完整。

改 2为什么松手才触发，而不是划到阈值马上触发

框架在转场开始的那一刻会把整个触摸设备复位 （lv_indev_reset(NULL, NULL)，见 gui_app_trans_anim.c:479）。 如果那时候手指还按在屏幕上，LVGL 会把"当前还按着"当成一次全新的按下并重新做命中测试 —— 而那一刻手指多半已经划到屏幕中间，正好落在蜂窝某个图标上，于是松手就把那个 app 点开了 （这也正是你更早反馈过的"误触"）。等松手再触发，这个问题从根上不存在。

即时反馈由指示条负责：越过 130px 的那一瞬间它就变蓝变实，不需要等到松手才知道"这一下算数"。

改 3返回动画换成 ease-out 平移，并且固定，不再随机轮换

框架喂给动画回调的是线性进度（lv_anim 没设 path_cb）， 线性平移的观感是"起步发木、落位发硬"。这里在回调里把进度重映射成 ease-out： 前半程走完 3/4，起步干脆、收尾软。两个页用同一条曲线，所以始终严丝合缝，不会露黑缝。

// src/gui_apps/utils/custom_trans_anim.c —— 线性进度 → ease-out inv = MAX - p; return MAX - (inv * inv) / MAX; // p=0→0 p=5000→7500 p=10000→10000

方向也固定了：进 app 时页面向左推、返回时向右退，进和出共用同一套配置， 所以不会再出现原厂那种"这次旋转、下次缩放"的随机演示动画。

改 4表盘和蜂窝上关掉这条手势

这两页是 app 栈的底：表盘往上没有"上一级"；蜂窝往上虽然能到表盘，但框架走的是 app_restart_last_suspend() —— 它会先销毁所有前台 app、 再重启被挂起的那个。 在表盘上划一下却弹出主菜单，显然不是想要的效果，所以这两页都关掉。

关闭时会连检测条的 CLICKABLE 一起清掉 —— 否则那条压在最右 16px 的透明检测条会继续吃触摸，蜂窝最右一列的图标就点不动了。
