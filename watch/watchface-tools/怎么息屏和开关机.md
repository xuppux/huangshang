# 息屏 & 开关机

## 结论先给

**硬件支持开关机，而且是三层都齐了 —— 之前没生效，只是缺一个编译开关。**

| 层 | 有什么 | 证据在哪 |
|---|---|---|
| **芯片** | PMU 能进 Hibernate（整机休眠），能被按键和 RTC 精准唤醒 | `drivers/Include/bf0_hal_pmu.h`：`HAL_PMU_EnterHibernate()` 的注释写着 "System can be woken up RTC and PIN precisely" |
| **板子** | 三级电源域 + I2C 充电管理，是真电池供电的板子 | `customer/boards/sf32lb52-lchspi-ulp_base/bsp_power.c`：PA38=VSYS、PA26=VCC_3V3、PA30=GS_3V3，充电 IC 地址 0x49 |
| **板子** | KEY1(PA34) 本来就是设计成关机唤醒键的 | SiFli 参考设计原注释：`PIN0 select: PA34 as pin0` |
| **代码** | 息屏 / 唤醒 / 长按关机确认框 / 10 秒无操作检测，全都写好了 | `middleware/system/gui_app_pm.c` + `src/gui_apps/watch_demo.c` |

## 一、为什么之前没有？—— 一个没打开的开关

那一整套 PM 代码，全部包在 `#ifdef BSP_USING_PM` 里面：

```c
#ifdef BSP_USING_PM
    if (lv_disp_get_inactive_time(NULL) > IDLE_TIME_LIMIT)   /* 10 秒 */
    {
        gui_pm_fsm(GUI_PM_ACTION_SLEEP);      /* 息屏 */
    }
#endif
```

而 `project/proj.conf` 里从来没有 `CONFIG_BSP_USING_PM=y`。

**官方 watch demo 自己也没开** —— 我把 `example/multimedia/lvgl/watch/project/proj.conf`
和我们这份逐行对过，完全一致，同样没有这一项。代码在仓库里躺了很久，编译器从来没看见它。

现在补上了三项：

```
CONFIG_BSP_USING_PM=y      # 让 PM 框架生效
CONFIG_GUI_APP_PM=y        # 才编译 gui_app_pm.c（息屏/唤醒状态机的实现）
CONFIG_PM_DEEP_ENABLE=y    # 52X 的 PM 模式 = Deep
```

> `GUI_APP_PM` 这一项特别容易漏：`middleware/system/SConscript` 里
> `gui_app_pm.c` 是按 `GetDepend(['GUI_APP_PM'])` 决定编不编的。
> 只开 `BSP_USING_PM` 的话，函数声明都在、实现却没有，链接期才会报错。

## 二、现在有什么

### 1. 10 秒无操作自动息屏（你要的）

不碰屏幕、不按键，**10 秒**后屏幕黑掉。

- 阈值在 `watch_demo.c`：`#define IDLE_TIME_LIMIT (10000)`，单位毫秒
- 息屏走的是 `RTGRAPHIC_CTRL_POWEROFF` —— 对 AMOLED 是让面板自己进睡眠，
  不是"调背光到 0"（AMOLED 没有背光可调，那样省不了电）
- 触摸屏也一并断电，所以息屏后**只有按键能唤醒**

### 2. 按 KEY1 唤醒

息屏状态下按一下 KEY1，屏幕亮、表盘继续走。

### 3. 长按 KEY1 关机

按住 KEY1 约 3 秒，弹出关机确认框，选 Ok 才真关。

关机 = 进 Hibernate：屏幕全黑、绝大部分电路断电。
**再按一下 KEY1 就开机**（重新启动，表盘恢复，RTC 时间不丢）。

### 4. 串口命令 `poweroff`

```
msh /> poweroff
power off: entering hibernate, press KEY1 to wake up
```

跳过按键和确认框，直接关机。**调试时用这个，见第五节的分段定位法。**

## 三、怎么调

| 想改什么 | 改哪里 |
|---|---|
| 息屏时间（10 秒 → 30 秒） | `watch_demo.c` 的 `IDLE_TIME_LIMIT`，改成 `30000`，重新编译 |
| 长按多久算"长按" | `rtconfig.h` 的 `BUTTON_ADV_ACTION_CHECK_DELAY`（现在 3000 ms），或 proj.conf 里加 `CONFIG_BUTTON_ADV_ACTION_CHECK_DELAY=1500` |
| 彻底不要关机功能 | 把 `watch_demo.c` 里 `pm_event_handler()` 的 `GUI_PM_EVT_SHUTDOWN` 分支注释掉 |
| 彻底不要息屏 | 把 `proj.conf` 里的 `CONFIG_BSP_USING_PM=y` 改成 `=n`，回到原来的样子 |

## 四、按键是怎么接上这套逻辑的

KEY1 一个键干了三件事，判断条件在 `watch_demo.c` 的 `button_event_handler()`：

```c
if ((SLEEP_CTRL_PIN == pin) && (!gui_is_active() || (action == BUTTON_LONG_PRESSED)))
{
    gui_pm_fsm(...);       /* 走 PM 状态机 */
}
else
{
    lv_disp_trig_activity(NULL);   /* 只是普通按键：重置"无操作计时"，并翻页 */
    ...
}
```

拆开看就是：

| 场景 | 发生什么 |
|---|---|
| 屏幕亮着，短按 | 不算 PM 事件 → 重置无操作计时 + 当 Home 键用 |
| 屏幕亮着，长按 3 秒 | 走 PM → 弹关机确认框 |
| 屏幕黑着，短按 | 走 PM → 唤醒 |

## 五、出问题怎么定位 —— 分段法

关机这条链其实有三段，任何一段断了表现都是"屏幕黑/不亮"，光看现象分不清。
**用串口命令把它切开来查：**

```
休眠通道：敲 poweroff ────────────→ 屏幕黑
唤醒通道：按一下 KEY1 ────────────→ 屏幕亮
开机确认：冷启动(拔插电) ─────────→ 表盘出来
```

| 现象 | 说明哪一段有问题 | 往哪看 |
|---|---|---|
| 敲 `poweroff` 屏幕就黑 | 休眠 ✓ | —— |
| 敲 `poweroff` 屏幕没反应 | 休眠这段 | `bf0_pm.o` / `gui_app_pm.o` 有没有编进来（看 map 文件），`BSP_USING_PM` 是否真的为 1 |
| 黑屏后按 KEY1 能亮 | 唤醒 ✓ | —— |
| 黑屏后按 KEY1 不亮 | 唤醒这段 | 开机日志里搜 `pm: wakeup ready`，确认 PA34 被识别成 AON 唤醒源；再查按键有没有接触问题 |
| 长按 3 秒没有确认框 | 按键→状态机这段 | 串口日志里应该有 `fsm:Cur[ACTIVE],Action[BUTTON_LONG_PRESSED]` |

**开机时会打印一行自检日志**，直接告诉你唤醒通路配好没有：

```
pm: wakeup ready  KEY1(pin 34) -> AON <n>  |  sleep=double-edge, hibernate=high-level
```

如果打出的是这条，说明这个板的 KEY1 不是 AON 唤醒源（换板子/改引脚才会遇到）：

```
pm: KEY1(pin 34) 不是 AON 唤醒源，息屏/关机后将无法用按键唤醒
```

## 六、实测记录（2026-09-20）

### ✅ 10 秒息屏：实测通过，有日志为证

烧录完接上串口监听，**不用看屏幕**就能验证 —— 状态机自己会打日志：

```
fsm:Cur[GUI_STATE_ACTIVE],Action[GUI_PM_ACTION_SLEEP]          ← 收到"该睡了"
change_gui_state:[GUI_STATE_ACTIVE]->[GUI_STATE_INACTIVE_PENDING]
no input:10028                                                  ← 无操作 10028ms（阈值 10000）
change_gui_state:[GUI_STATE_INACTIVE_PENDING]->[GUI_STATE_INACTIVE]
gui_suspend                                                     ← 挂起 GUI 线程
drv.lcd lcd_task: Power off                                     ← 关屏
drv.lcd lcd_task: display off
drv.lcd lcd_task: [ON] -> [OFF]                                 ← 屏幕状态真的翻了
drv.lcd lcd_task: HW close
TOUCH tp_off: Power off                                         ← 触摸也断电
```

`no input:10028` 这个数字最直接：它就是要的 10 秒，多出来的 28ms 是 30ms
轮询周期带来的。

## 七、两个约束（来自芯片，不是随便填的）

关机唤醒用的是 PMUC 域的寄存器，和息屏唤醒（HPAON 域）**完全是两套**，
少配一边就会出现"关得掉、开不了"。

1. **唤醒引脚编号只能是 0 或 1** —— 芯片里 `PMUC_WSR_PIN_ALL` 就只包含 PIN0/PIN1
2. **电平用"高"** —— KEY1 是高电平有效（`BSP_KEY1_ACTIVE_HIGH 1`），
   按下时引脚被拉高，所以要让 PMU 在高电平上唤醒

这两条已经写进 `watch_demo.c`，启动时配一次就一直有效（寄存器在掉电前保持），
不用等到关机那一刻再配。
