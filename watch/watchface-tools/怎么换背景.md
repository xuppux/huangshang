# 表盘资源工具 · 用法

这个目录里的脚本负责生成「手环风」表盘用到的所有图片，以及 C 代码要用的排版常量。

```
watchface-tools/
├── make_assets.py        ← 生成贴图 + wf_layout.h + 预览图（改字号/配色就改这里）
├── analyze_assets.py     ← 自检：有没有被裁切 / 会不会超宽 / 白字够不够清楚
├── font_diag.py          ← 排查字体问题用（正常情况下不用跑）
├── fit_diag.py           ← 排查字号选择问题用（同上）
├── make_assets.log       ← 上次生成的结果摘要
├── asset_metrics.txt     ← 上次自检的完整报告
└── 怎么换背景.md          ← 本文件
```

跑脚本用的 Python（装了 Pillow 的那个，别用别的）：

```
C:\Users\18058\.workbuddy\binaries\python\envs\default\Scripts\python.exe make_assets.py
```

## 一、只想换背景图（最常见的需求）

表盘的背景就是**一个文件**：

```
lvgl\watch\src\resource\images\common\large_ezip\wf_bg.png
```

要求很简单：**390 × 450 像素**，PNG 或 JPG 转成 PNG 都行。替掉它，重新编译，就换好了。
不用改任何 C 代码，也不用跑生成脚本。

做图建议：

- 找一张竖屏比例的图，先裁成 390:450（大约 13:15）再缩放到 390×450，别硬拉变形。
- **主体别放在中间偏上**——时间数字在 y=140~245，日期在 y=259~296，正好压在这里。
  风景照把地平线放在下方、把天空留出来，效果最好。
- 人脸、logo 这类有明确主体位置的图，把主体挪到上半部分（y < 130）或者最下面（y > 310）。
- 图别太亮。白字压在亮背景上会看不清——文字下面垫了一层柔和的压暗（见第二节），
  但如果原图中间就是一片白，还是会有点糊。

## 二、那片"压暗"是什么，能不能去掉

`wf_scrim.png`（同一目录）是一层 390×450 的半透明黑，中间深、边缘羽化到全透明，
专门垫在时间和日期下面。

它的作用是：**换成任何一张照片，白字都还读得清。** 自检脚本会量出来（见下），
默认背景下时间行的对比度是 18.4，远高于"能看清"的门槛 4.5。

- 想去掉：把 `app_clock_band.c` 顶部的 `#define WF_USE_SCRIM 1` 改成 `0`。
- 想调深浅：改 `make_assets.py` 里 `make_scrim()` 的 `a_max`（现在 135），数字越大越黑。
- 压暗层只有中间一块，所以照片的四角基本保持原样，不会整张发灰。

## 三、想调字号 / 配色 / 留白

改 `make_assets.py` 顶部的 CONFIG 区，然后重跑。**C 代码不用动**——
所有几何常量都是生成脚本量出来的实际尺寸，写进 `wf_layout.h` 给 C 用。

常用的几个：

| 想改什么 | 改哪一行 |
|---|---|
| 数字多大 | `ROW_MARGIN`（越小数字越大，现在是 10） |
| 整块内容的上下位置 | `GROUP_CENTER_Y`（现在是 218，屏幕中心是 225） |
| 时间和日期之间的间距 | `DATE_GAP` |
| 日期那行字多大 | `SMALL_TARGET_H`（现在是 24） |
| 深底白字 / 浅底黑字 | `THEME = 'dark'` 改成 `'light'` |
| 数字之间的松紧 | `GAP_BIG` |
| 日期行内部的松紧 | `DATE_ITEM_GAP`（现在是 0，即只用贴图自带的 3px） |

另外两个开关在 `app_clock_band.c` 顶部，不用重跑脚本：

| 想改什么 | 改哪一行 |
|---|---|
| 冒号闪不闪 | `WF_COLON_BLINK`（`0` = 常亮，`1` = 每秒闪一下） |
| 要不要那层压暗 | `WF_USE_SCRIM` |

改完重跑生成脚本 + 自检脚本，然后编译。

**为什么字号不能直接在 C 里改？** 因为数字是预先渲染好的图片，不是用字体实时画的。
好处是零渲染开销、绝对不会因为字库差异变形；代价是换字号必须重新生成图片。
本工程能用于大号字的字体只有 FreeType 那条路，而自带的 `tiny55_full.ttf` 是
16×16 点阵自压缩字体，放大会糊成一团——所以走预渲染是更稳的选择。

## 四、生成完一定要跑一遍自检

```
...python.exe analyze_assets.py
```

报告写在 `asset_metrics.txt`，一共七项：

1. **有没有被裁切** —— 描边或投影贴到画布边缘就是被裁了，会看到缺角。
   生成脚本用的是"先画再量、按实际像素裁"的办法，正常情况下必须是 `裁切问题: 0 个`。
2. **会不会超宽** —— 时间行必须 ≤ 370（屏宽 390）；日期行按
   1月2日 / 9月20日 / 10月8日 / 12月30日 四种长度各算一遍。
3. **等宽单元的居中是否一致** —— 每个数字在自己格子里必须水平居中，偏差应在 ±0.5px。
   偏差大了，分钟跳变时整行会左右抖。
4. **白字够不够清楚** —— 按 WCAG 算对比度，低于 3.0 会提示"需要更强的压暗层"。
5. **日期行元素顺序** —— 把「<月>月<日>日」独立解析一遍，再和贴图序列逐项比对。
   这一步专门防"月份数字漏掉 / 月和数字顺序写反"这类错误。
6. **C 代码布局检查** —— 直接扫 `app_clock_band.c`：冒号有没有设图源、月份个位
   有没有排进去、「月」「日」是不是排在数字后面。**这类错误 PC 预览完全看不出来，
   只会在板子上显形**，所以必须在这儿挡住。
7. **负向自测** —— 把上一版写错的代码喂给检查器，它必须报 FAIL。
   一个永远不报错的检查等于没有，这一项就是证明它不是摆设。正常输出：
   `抓出 3 项 FAIL` + `关键项是否被抓住: 是`。

## 五、校时

表盘显示的是 RTC 里的真实时间。**第一次上电 RTC 是空的**，显示 2024-01-01 12:00。
接上 shell（finsh），敲：

```
show_date 2026 9 20 18 30 0        # 年 月 日 时 分 秒
```

只敲 `show_date` 不带参数，就是查看当前时间。

> 说明：`watch_demo.c` 里原来硬写着开机就 `set_date(2022,7,1); set_time(9,0,0);`，
> 每次启动都把 RTC 冲掉，所以表盘永远显示 2022-07-01 09:00。现在改成了
> "只有年份小于 2024 才兜一个默认值"，RTC 里是真时间就原样保留。

## 六、时间是怎么变成"真"的

一句话：**每秒去问一次 RTC 硬件，不是自己数秒。**

```
LXT 32.768kHz 晶振
      ↓
SF32LB52 片内 RTC 计数器           ← 独立晶振，走时准（不是内部 RC）
      ↓
RT-Thread RTC 驱动 drv_rtc.c      ← BSP_USING_ONCHIP_RTC = 1
      ↓
time()  →  rt_device_find("rtc")
        →  rt_device_control(..., RT_DEVICE_CTRL_RTC_GET_TIME)
      ↓
localtime()  →  struct tm（年 月 日 时 分 秒 星期）
      ↓
band_refresh()                     ← lv_timer 每 1000ms 触发一次
      ↓
查表取数字贴图 big_digit[时/10] …  →  LVGL  →  CO5300 AMOLED
```

关键在于**最后一步前面没有任何"从上电开始累加"的中间变量**：`band_refresh()`
每次都重新调一次 `time()` / `localtime()`。所以：

- 用 `show_date` 改完时间，**1 秒内**屏幕就跟着变（不用重启表盘，也不用重烧）。
- 复位、重烧、反复开关串口都不影响它。
- 为了省电，只有在"分钟真的变了"或"换日了"的时候才去动贴图，秒不变不重绘。

对比一下框架自带的那几个表盘（`simple` / `dial` / `rotate_bg`）：它们走的是
`app_clock_main_get_current_time()`，进入表盘时把 `localtime()` **快照一次**
（就是日志里那行 `service_reset_time`），之后靠 `clock()` 的 tick 累加。
所以它们改了 RTC 不会立刻反映，要退出再进表盘才会重新对表。

### 两个已经踩过的坑（都上过板子）

**坑 1：`lv_img_create()` 出来的对象是空的。**
冒号那个对象建了、位置也摆了，但漏了 `lv_img_set_src()`，屏幕上就是"没有冒号"。
对象存在、坐标也对，就是没内容 —— 这种错**日志里一个字都不报**。

**坑 2：日期行的元素顺序写反，还漏了一个。**
原代码是「[月] → 再排数字」，而且月份个位压根没排进去，屏幕上显示成「月20日」。
正确顺序是**数字在前、单位在后**：`9月20日`。

这两类错误现在都由 `analyze_assets.py` 的第 6/7 项挡住，并且用"故意写错的代码"
做过反向验证，确认它真的会报 FAIL。

## 附：表盘在代码里长什么样

```
lvgl\watch\src\gui_apps\clock\
├── app_clock_band.c      ← 表盘本体（时间行 / 日期行 / 背景 / 每秒定时器）
├── wf_layout.h           ← 自动生成，几何常量
└── app_clock_main.c      ← 在这里注册：app_clock_band_register()

lvgl\watch\src\resource\images\common\
├── ezip\                 ← 数字、冒号、日期小字（scons 自动编译，不用手动登记）
│   wf_d0..wf_d9  wf_colon  wf_s0..wf_s9  wf_ym  wf_yd  wf_w1..wf_w7
└── large_ezip\
    ├── wf_bg.png         ← 背景（换成你自己的图）
    └── wf_scrim.png      ← 压暗层
```

注册顺序就是表盘顺序，第一个注册的是开机默认表盘。`app_clock_main.c` 里
`app_clock_band_register()` 排在所有表盘前面，所以开机会直接进这个表盘。
不想再看到原来的几个表盘，把后面几行 `register()` 注释掉即可。

左右滑动可以切换表盘（框架自带），`wf_layout.h` 里的尺寸不会影响其它表盘。
